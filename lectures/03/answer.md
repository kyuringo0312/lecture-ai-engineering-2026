## 宿題

- 取り組んだレベル：**基礎 / 実装 / 発展（a）（3 つすべて）**

### 基礎：INSTRUCTIONS と docstring を 1 か所ずつ変えて比べる

- やったこと：`scripts/compare_instructions_lec03.py` で，`app/agent.py` と同じツールを登録したエージェントを変更点ごとに組み立て直した．各変更点で，同じ 2 問を 2 回ずつ実行し，ツール呼び出し，`requests`，トークン数，回答を記録した（`results/basic.jsonl`）．ファイルを毎回書き換える代わりにスクリプトで組み立てたが，変えたのはどれも 1 か所だけである．
  - `base`：元のまま
  - `no_must_search`：`INSTRUCTIONS` から「必ず search_glossary で用語集を確認する」の行を消す
  - `doc_bulk_query`：`search_glossary` の docstring を「用語を1つだけ入れる」から「まとめて入れる（例: "LoRA QLoRA"）」に変える
  - `quiz_at_end`：`INSTRUCTIONS` の「回答の最後に，関係する回（第N回）を示す」を「回答の最後に，確認問題を1問出す」に変える
- 結果（各 2 回．どの版も `requests` は 2 回，用語の質問では毎回検索した）：

| 変更 | 「LoRAとQLoRAの違いは？」の検索 | 入力トークン（LoRA / lecNN） | 回答の変化 |
|---|---|---|---|
| base | `LoRA`，`QLoRA` の 2 回 | 1,714 / 1,301 | 4 回とも最後に「第N回」 |
| no_must_search | `LoRA`，`QLoRA` の 2 回（変化なし） | 1,666 / 1,253 | 変化なし |
| doc_bulk_query | `LoRA QLoRA` の **1 回** | 1,409 / 1,303 | 内容は変わらず正しい |
| quiz_at_end | `LoRA`，`QLoRA` の 2 回 | 1,706 / 1,293 | 4 回とも確認問題が付き，「第N回」は 4 回中 3 回で消えた．出力は 196〜213 → 287〜379 トークンに増えた |

- 追加の検証：「必ず検索する」を消しても検索をやめなかったので，ツールの docstring の「答える前に使うこと」が効いていると考えた．そこで，指示と docstring の**両方**から「先に検索する」を消した版も試した（2 か所を同時に変えるので，上の比較とは分けて扱う）．結果は 4 回とも検索した（`results/basic_extra.jsonl`）．この仮説は外れた．
- 気づき・疑問：
  - **指示に書かなくても，モデルはツールを使う**．講座固有の語を聞かれ，「講座の用語集から用語を検索する」ツールが目の前にあれば，指示が無くても使った．今回の質問に限れば，「必ず検索する」の行は無くても結果が変わらなかった．逆に言えば，検索させたくない場面でも使ってしまう可能性がある．
  - **docstring の書き方は，引数と回数にそのまま効く**．「まとめて入れる」にすると，検索が 1 回に減り，入力も約 300 トークン減った．ただし正しく答えられたのは，この検索が部分一致で `"LoRA QLoRA"` から両方の用語を拾えたからである（試すと `LoRA` と `QLoRA` の 2 件が返った）．検索の作りが違えば，まとめた検索語では何も見つからない可能性がある．docstring はツールの実装と合わせて書く必要がある．
  - **指示は置き換わる**．「最後に確認問題を出す」に変えると，「第N回を示す」は消えた．指示を足すつもりで書き換えると，元の振る舞いが失われる．出力が増えるぶん，コストも増える．
  - 各版 2 回ずつなので，回答の文面の差は揺れの範囲の可能性もある．ツールの呼ばれ方は 2 回とも同じだった．

### 実装：save_learning_log を承認付きで作る

- やったこと：
  - `app/tools.py` に `save_learning_log(title, content)` を作った．`learning_log/` に日時付きの Markdown を保存する（`learning_log/` は `.gitignore` 済み）．
  - `app/agent.py` で `agent.tool_plain(tools.save_learning_log, requires_approval=True)` と登録し，`output_type=[str, DeferredToolRequests]` にした．
  - CLI に `ask_approval` / `run_with_approval` を足した．`DeferredToolRequests` が返るたびに，呼び出し（ツール名と引数）を見せて「実行してよいですか？ [y/N]」と聞く．`y` なら `True`，それ以外なら `ToolDenied` を `DeferredToolResults` に入れ，`message_history=result.all_messages()` と一緒にもう一度 `run_sync` する．入力が無い（EOF）ときは実行しない側に倒した．
  - テスト（`tests/test_lec03.py`）は API キーなしで動く．承認待ちで止まり何も書かれないこと，承認すると 1 ファイル保存されること，断ると保存されないことを `TestModel` で確かめた．
- 結果：
  - **1 回目は失敗した**．docstring に「保存は取り消しにくいので，実行の前に利用者の承認を求める」と書いたところ，モデルはツールを呼ばず，「保存してよろしいですか？『保存してください』とお知らせください」と**文章で聞き返して終わった**（`results/impl_approve.txt`，`impl_deny.txt`．保存は 0 件）．モデルは「承認を求める」を自分の仕事だと読んだ．
  - docstring を「保存を頼まれたら，利用者に聞き返さずにすぐこのツールを呼ぶ．実行してよいかの確認は，システムが利用者に直接行う」に直すと，期待どおりに動いた（`results/impl2_*.txt`）．
    - 承認した場合：`[承認待ち] save_learning_log({'title': 'LoRAとQLoRAの違い', 'content': ...})` で止まり，`y` で 1 件保存された．
    - 断った場合：`n` で保存されず（1 → 1 件），モデルは「保存を試みましたが，実行がキャンセルされました」と伝えた．
  - 保存したファイルは見出しが二重になっていた．モデルが本文の先頭にも「# 題名」を書いたためである．本文が見出しで始まるときは重ねないように直し，テストを足した．
- 気づき・疑問：
  - **承認を「誰が」取るかを，説明文で明確にする必要がある**．Human-in-the-loop の仕組みはハーネス側にあるのに，説明文で承認に触れたことで，モデルが自分で同じことをしようとした．文章での「よろしいですか？」は，ハーネスが確かめる承認とは違い，何も止めていない．
  - 承認画面にはモデルが作った引数（保存する本文）がそのまま出るので，何を保存するかを人が見て判断できる．再開後の `[usage]` は再開した実行の分（`requests=1`）だけなので，質問全体の回数は 1 回目の実行と足して数える必要がある．

### 発展（a）：ADK で作り直す

- やったこと：`adk_agent/glossary_agent/agent.py` で，`INSTRUCTIONS` と `search_glossary`・`get_lecture_summary`・`make_quiz` をそのまま使い，`google.adk.agents.Agent` で組み立てた（`google-adk` 2.14.0）．`adk run --replay adk_agent/replay_lec03.json` で，演習と同じ 3 問を対話なしで流した．
- 書き方の違い：

| | Pydantic AI（`app/agent.py`） | ADK（`adk_agent/glossary_agent/agent.py`） |
|---|---|---|
| 指示 | `Agent(instructions=INSTRUCTIONS)` | `Agent(instruction=INSTRUCTIONS)` |
| ツール | `agent.tool_plain(関数)` で 1 つずつ登録 | `tools=[関数, ...]` にまとめて渡す |
| モデル | 実行時に `run_sync(..., model=...)` で渡す（テストで `TestModel` に差し替えるため） | 組み立てるときに `model="gemini-3.5-flash-lite"` と名前で決める |
| 動かし方 | 自分で書いた CLI（`--trace` など） | `adk run` が対話の画面を用意する．エージェントは `root_agent` という名前で置く決まり |

- 回答の違い：3 問とも内容は同じ方向だった．「3レベル」は基礎・実装・発展とどれか1つで完了，「LoRAとQLoRA」は用語集の定義どおり，確認問題は「「ランク（LoRAのr）」の意味は？」（2 回目は「「事前学習」の意味は？」）を出し，答えは見せなかった．問題文が `make_quiz` の返り値の形そのままなので，ツールが呼ばれたと考えられる．ただし `adk run` の画面にはツール呼び出しが出ず，ログ（`/tmp/agents_log`）にも残らなかったので，呼び出しの引数までは確かめられていない．
- 気づき・疑問：
  - 同じ指示とツールの説明（docstring）を渡すと，フレームワークを変えても振る舞いはほぼ同じだった．エージェントの性格を決めているのは，フレームワークよりも，モデル・指示・ツールの説明だと感じた．
  - 差が出たのは周辺である．Pydantic AI は呼び出しを自分で表示でき，`TestModel` で API なしにテストできる．ADK は対話の画面がすぐ使えるが，ツール呼び出しを見るには別の仕組み（`adk web` など）が要りそうである．
  - 初回の `adk run` は利用データ送信の確認（`Enable telemetry? [Y/n]`）で入力待ちになり，対話なしの実行が止まった．送信しない（`n`）と答えて進めた．自動で動かすときは，こうした初回の確認にも気を付ける必要がある．
